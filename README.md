# TSMP 工资单

门店月度工资计算器：按员工录入业绩和实际休息天数，确认后导出图片或 Word。所有记录保存在当前浏览器 / App 的本机存储中，不上传员工工资数据。

## 每个月怎么用

1. 第一次点击 **启用休假账本**，选择起始月份，填写每位员工以前攒下的休息余额。没有余额也需要明确填 `0`，可点“所有人均无结余，全部填 0”。
2. 顶部选择工资月份，填写本月总店业绩。左右滑动或点姓名进入员工页面，填写个人业绩、送货趟数、其他增减和 **实际休息天数**。
3. 点 **存为图片** 或 **存为 Word**，核对实发工资、上月结余和结转下月天数，再点 **确认并生成**。
4. 导出的文件按原来的方式发给员工。确认只代表记录已保存，不代表发薪、发送或员工签收。
5. 下个月自动带入上月剩余。补存图片或 Word 不会重复结转。

输入过程自动保存草稿。每位员工按月连续确认，漏填月份要补录；未填写休息天数不能当作零天。如果实际没休息，请明确填 `0`。

## 休假与扣薪规则

所有员工（包括店长）每月新增 **2 天** 正常休息，未用完的余额持续累计、跨年保留。支持半天，最小单位 `0.5` 天。

- 本月可休＝上月结余＋2 天。
- 下月结余＝`max(0, 本月可休－实际休息)`。
- 超额天数＝`max(0, 实际休息－本月可休)`。
- 可休额度以内不扣工资和全勤奖；超额时扣整笔全勤奖，再按日薪基数÷当月天数×超额天数扣款。店长没有全勤奖扣款。
- 不预借未来月份额度，余额不会出现负数。

例：5 月休 1 天，留下 1 天；6 月可休 3 天，休满 3 天不扣款，留到 7 月为 0 天。

| 岗位 | 底薪 | 日薪基数（不含全勤） | 全勤奖 |
|---|---:|---:|---:|
| 店长 | 8,000 | 8,000 | 无 |
| 销售 | 4,500 | 4,000 | 500 |
| 财务 | 6,800 | 6,700 | 100 |
| 配送 | 5,800 | 5,700 | 100 |

业绩始终按 **元** 填写。店长总店提成：总店满 60 万后提千分之一。店长及销售个人业绩按 A/C/D＋B 合计定档：满 15 万分别提 1% / 0.5%，满 20 万分别提 2% / 1%，不是累进计算。财务及配送总店业绩满 40 万，每完整 10 万奖 100；满 60 万全部档位改为每 10 万 200。配送每趟 15 元。其他增减支持负数。

## 改错与历史记录

选择原月份修改即可保存新的草稿。已确认的旧快照会保留，该员工后续已有确认记录标为 **待核对**，需要按时间顺序重新确认。重新确认后，“查看确认记录”保留各版实发、休息和余额。

总店业绩影响同月各人工资单，修改后同月及后续相关确认记录都需要核对。修改不会自动更新已经保存在相册、下载或发出的旧文件，请核对后重新导出新版。

“清空本月草稿”只清空没有确认快照的输入。有确认快照的记录（包括待核对版本）、其他月份、初始余额均保留。如果本月已有确认快照，总店业绩也不会被清空。

## 工资单

图片与 Word 从同一份已确认快照生成，包含本月数据、休息明细、固定工资、提成奖金、扣款和实发合计。单子展示结果，详细公式留在计算页面。休息明细包含上月结余、本月新增、实际休息、结转下月；超额时另列超额天数。

汇总页的复制、打印要求本月全部员工已经确认，使用同一份数据。Word 沿用兼容旧流程的 HTML `.doc` 格式。

## 备份与恢复

- 点击 **备份与恢复 → 导出当前账本**，下载 JSON 文件。换手机前请先备份；不同浏览器、Safari 和 App 之间不自动同步。
- 恢复可选择 JSON 文件或粘贴内容。检查版本、月份和记录数量后确认，**整体替换**当前账本，不合并多设备记录。
- 恢复前会自动保留当前账本，可通过“导出恢复前备份”取出。恢复前备份只保留最近一次；长期归档请手动导出。
- 老版 `tsmp-salary-v1` 不会删除；首次迁移同时保存一份原始备份，输入保留在原月份的未确认草稿。启用前月份只供查看，不自动推算历史余额。
- 保存失败时会明确提示，不能完成确认。屏幕上的失败输入会暂时保留，但导出备份只包含已经成功保存的记录。
- 若原账本损坏，可先“留存原始数据”，再从有效备份恢复。不要通过卸载 App 或清除浏览器数据来尝试修复。

## 开发与验证

无需构建或外部前端依赖。本地运行：

```sh
python3 -m http.server 8793 --bind 127.0.0.1
```

打开 `http://127.0.0.1:8793/`，不要直接双击 HTML 文件运行。

```sh
node --test tests/ledger.test.cjs
python3 tests/browser.py
python3 tests/browser-safety.py
```

浏览器测试需要 Python Playwright 以及 Chromium / WebKit（`python3 -m playwright install chromium webkit`）。可用 `TSMP_TEST_URL` 指定本地地址，`TSMP_QA_DIR` 指定导出验证产物目录。

- `payroll-core.js`：原工资公式和统一的可休额度入口。
- `ledger.js`：版本 2 月份账本、确认快照、历史修正、迁移及备份校验。
- `app.js`：录入、核对、历史、备份恢复与复制打印。
- `exports.js`：共用工资单分段、图片和 Word 导出。
- `index.html`：页面结构、纸色金线样式和手机适配。

已有 iOS App 继续通过 WKWebView 加载同一个工资页，沿用本机数据存储和系统下载分享。不变更 App 的房租账本或 GC 工资工具。
